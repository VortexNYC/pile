# Architecture

```
HTTP/MCP/CLI ──► Hono app (zod-openapi)
                    │
                    ├──► D1 (Drizzle) ── workspaces, users, tickets, sessions, CRM
                    │
                    └──► WorkspaceDO (SQLite) ── issues, comments, history, links
                           one instance per workspace
```

## The contract pipeline

Route definitions are the single source of truth:

```
src/api/*.ts (Hono + zod-openapi)
        │
        ├──► src/mcp/openapi.json   — generated spec
        ├──► src/mcp/mcp-tools.ts   — generated MCP tools
        └──► packages/cli/src/      — generated client + commands
```

`pnpm run contract` regenerates all three; `contract:check` fails a PR if they drift. New routes automatically become API + MCP + CLI surface — that is why the tool count is 600+ and always in sync.

## State split

- **D1 / Drizzle** — global metadata: workspaces, users, support tickets, agent sessions, customers, deals. Queryable across workspaces by operators.
- **WorkspaceDO** — per-workspace mutable state: issues, comments, issue history, entity links. One Durable Object instance per workspace keeps writes strongly consistent and fast.

## Auth

- **Humans**: Better Auth (sessions, orgs, SCIM).
- **Agents**: workspace-scoped API keys (better-auth `apiKey` plugin) — metadata pins `organizationId`; the key can't act outside it.
